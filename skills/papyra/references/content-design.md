# 内容设计

先问读者需要理解或决定什么，再选择表达。富内容意味着已有信息的关系更容易看见，不意味着新增未经支持的事实。

## 从关系选择表达

| 原文关系 | 可考虑的表达 | 必须保留 |
| --- | --- | --- |
| 章节与层级 | 目录、锚点、当前位置、分区 | 完整正文与上下文 |
| 过程与阶段 | 步骤、时间线、流程图 | 顺序、条件、异常与返回路径 |
| 状态转换 | 状态图、条件展开、关联说明 | 所有允许的转换与终止规则 |
| 方案比较 | 对照表、切换或并排阅读 | 同一比较口径、缺项及各自风险 |
| 数字与比例 | 图表、面积比例、目标进度 | 单位、分母、时间区间与统计口径 |
| 概念与依赖 | 关系图、术语解释、关联跳转 | 方向、关系类型与原文依据 |
| 论点与证据 | 结论概览、证据展开、引用回溯 | 出处、限定条件与不确定性 |
| 示例与代码 | 示例切换、复制、解释并置 | 原始代码、格式与完整示例 |

这些不是组件配额。一份文档可以混合多种关系，也可能只需要优秀的连续排版。

## 阅读顺序

- 首屏让读者接触真正内容：结论、问题、当前步骤或比较对象。导航与工具不抢占主要阅读空间。
- 短文以连续阅读为主；长文增加定位能力；复杂文档同时提供主线与细节入口。
- 折叠适合冗长的补充说明，不将关键条件、风险或主要结论默认隐藏。
- 图形靠近对应解释。读者应能从图回到数据、条件或章节，不依赖仅在悬停时出现的信息。
- 不把所有段落都卡片化，不把原文拆散到难以搜索或无法连续阅读的多个视图。

## 原文与增强表达

完整保留内容及含义，允许改善排版与分组。确需重排时保留流程顺序、引用和上下文关系，不丢失信息。

- 原文结论与生成摘要明确区分。
- 图形只能呈现原文支持的关系。功能面积比例不等于实测平面图，状态示意不等于业务运行结果。
- 计算注明公式、假设和单位。没有数据的地方显示缺失，不填零、不插值、不生成“合理”数值。
- 计算器验证空值、负数、上限及单位；结果不能冒充预测承诺。
- 保留必要的“估算”“假设”“示意”与来源说明；不能为了画面纯净而删掉。
- 无法确定的关联不画成确定因果关系。

## 交互的选择

每个交互都能回答一个阅读问题：快速找什么、展开什么、比较什么、改变哪个参数来理解什么。

目录、原生折叠、代码复制、方案切换通常足够。按需增加筛选和试算，不机械加入搜索、阅读进度、主题切换或所有可能的控件。

状态改变应立即交出可观察的结果，并保留返回或清除入口。涉及浏览器存储时说明作用范围，并在存储不可用时保持基本阅读。

## 场景举例

- 运营报告：关联数据、发现、行动与停止条件，不只陈列大数字。访问量、转化率和成本应保留各自口径。
- 需求规格：让约束、状态、异常和测试用例相互关联，不把接口草案表现为已上线服务。
- 设计方案：同步比较选择影响的容量、成本和风险，不为缺乏依据的方案补造面积或效果图。
- 教程：保持先决条件与操作顺序，提供示例与代码入口，不自动执行读者看到的命令。
