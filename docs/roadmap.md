# Papyra 改进路线

更新日期：2026-10-22。本文为功能计划，不代表下列能力已经完整实现或验证。

## 产品方向

Papyra 以自包含 Skill 为唯一产品入口，复用宿主 Agent 的模型、文件工具、浏览器与权限控制。下一步优先扩展文档的**数学表达、图形表达和证据溯源**，而不是建设调用与评测框架。

不开发独立生成 CLI、Agent 调用适配器、任务编排或自建沙箱。安装命令及样例构建、检查脚本保留。全新上下文冒烟、真实图片验证与自动检查用于支持具体功能交付，不再单独占据产品路线的前三位，也不作为全部新功能的前置项目。

## 当前基线

- 已交付自包含 Skill 0.3.0、内容与视觉指导、重点标注资源及三份离线 HTML 样例。
- 最近三份样例的标注为 12、13、13 处；下划线 3px、圈注 2.5px。样例检查覆盖原文、离线移动、打印、无脚本退化及多视口等布局状态。
- Skill 已指导使用内联 SVG，现有样例也有 SVG 图形；下一步是完善原图保留、LLM 生成图形、可读性与安全边界，不是从零引入 SVG。
- 数学公式尚无明确的离线渲染契约；引用回溯已有原则，但尚无完整的“正文标记—证据说明—原始来源”交付规范。
- 样例成功不代表全新上下文、跨模型或任意输入稳定。历史记录见 [三案例回测](papyra-0.3.0-sample-retest.md)，当前规则见 [Skill](../skills/papyra/SKILL.md)。

## 核心改进与交付顺序

三项均为核心功能，序号表示建议实施顺序，不表示后项价值较低；彼此不依赖独立 CLI 或通用校验器。

| 顺序 | 能力 | 用户价值 | 完成门槛 |
| --- | --- | --- | --- |
| 1 | 数学公式 | 技术、研究和教学文档能准确表达公式，不再依赖原始 LaTeX 文本或公式截图 | 行内、块级公式离线正确显示；原始表达式可取回；窄屏、打印和错误反馈经过实测 |
| 2 | 原生 SVG 显示与 LLM 生成 | 将关系、流程、结构和几何内容直接转成清晰图形，不依赖外部绘图服务 | 保留输入图形信息，生成图形有原文依据；单文件离线显示，窄屏可读且有等价文字说明 |
| 3 | 引脚式引用与来源追溯 | 读者能从结论找到证据、参考文献、原出处与原网址，而不仅看到一个裸链接 | 引用、证据与来源逐一对应，支持正文跳转和返回；缺失、未核验及新增资料明确区分 |

## 1. 数学公式

### 实施范围

- 明确 Markdown 的行内与块级 LaTeX 分隔规则，覆盖转义、代码块中的公式文本及货币符号，避免将普通文本误判为公式。
- 使用成熟、可离线工作的公式渲染方案，优先在生成阶段完成转换并内嵌必要样式与字体；不能要求读者安装依赖，不使用 CDN。具体渲染器通过代表公式的实际显示结果确定，不由 LLM 手工重写复杂公式。
- 保留原始 LaTeX，提供复制或查看原式入口；公式编号、条件、单位与正文引用关系保持一致。可检索的原式与视觉公式避免形成屏幕阅读器的重复朗读。
- 覆盖分式、根式、上下标、求和、积分、矩阵与多行对齐。宽公式局部滚动或合理拆行，不挤坏正文；渲染失败显示原式并报告问题，不冒充转换成功。
- 公式与相邻文字的字号、基线、深浅底色及打印统一检查。保留可访问的数学结构或等价表达，不能只交付不可选择的公式图片。

### 验收

用一份包含上述构造、中文混排及错误语法的真实代表文档验证：断网移动单文件仍可显示；原式可复制；320px/390px 不产生整页横向滚动；打印保留公式与编号；错误能准确定位。公式显示正确不代表数学推导已核验，不自动改写原式。

## 2. 原生 SVG 显示与 LLM 生成

### 实施范围

- 区分两类图形：输入自带 SVG 是原文资源，保留其内容与出处；LLM 根据正文生成的示意图是阅读增强，标记生成属性，不替代原文，也不冒充实测图或原始证据。
- 允许 LLM 直接生成自包含的内联 SVG，用于结构、流程、关系和必要几何表达；不强制先经过 Mermaid、外部绘图 API 或栅格化。图形服务于理解，不作为每篇文档的配额。
- 图形使用合适的 `viewBox`、响应式尺寸、可读标签和主题适配；复杂图在窄屏采用分图、局部缩放或等价文字结构，不把整图缩成不可读的小字。
- 提供图题与可访问说明；关系、方向、单位、比例和条件均有原文依据。输入 SVG 的文字、标签和来源不能因安全处理或排版而静默丢失。
- 将 SVG 作为静态图形处理：不执行脚本、事件属性或外部资源引用，不通过 `foreignObject` 引入活动内容；不能可靠处理的输入明确报告，不宣称任意 SVG 都兼容。
- 静态图不依赖 JavaScript；必要的关联交互由生成页面的受控逻辑实现，并有键盘入口与文字替代。布局变化后复用现有标注刷新机制。

### 验收

同时使用一份带本地 SVG 的文档和一份适合 LLM 直接绘图的文档，检查原文图形与增强图的区分、离线显示、窄屏文字、深浅主题、打印与可访问说明；用含脚本或外部引用的输入验证安全边界。原图无法完整安全呈现时报告限制，不悄悄交付缺失信息的图。

## 3. 引脚式引用与来源追溯

这里的“引脚”指正文中的编号引用标记（如 `[1]`），可定位对应的证据说明、脚注或参考来源；不是评论系统或用户批注管理器。

### 实施范围

- 支持 Markdown 脚注、参考链接及参考文献区，将正文标记、注释内容和来源条目关联；保留原有引用标识和阅读关系。普通解释性脚注不强制拥有网址。
- 来源条目按已有信息展示标题、作者或机构、发表日期、原始网址、页码或章节；网页补充访问日期。缺失字段明确缺失，不补造作者、日期、DOI、页码或链接。
- 引脚附近可展开证据摘录或简短说明，文末保留完整来源列表；点击能到达来源并返回原引用位置，同一来源被多处引用时每处均可返回。触屏、键盘和无脚本情况下仍可使用基本锚点导航。
- 区分“原文提供的来源”和“Agent 补充的来源”。用户要求补充证据，或页面新增解释需要外部依据时，使用宿主可用的检索与读取工具查阅原始资料，新增内容独立标记，不混进原文。
- 引用要支持相邻的具体论断，不能只因主题相近就挂上链接；摘录逐字可核对，转述标明为转述。优先指向实际查阅的原出处，只有二手来源时标明转引关系，不把未读取的上游资料写成已核验。
- 原文给了网址但未实际访问时标为未核验；工具不可用、链接失效或证据不足时如实说明，不自动宣称已验证。存在真实来源也不等于结论必然成立。
- 单文件内保存脚注、来源元信息及必要证据说明，离线仍可读；打开原始网址需要网络，不能把外部网页可用性计入离线承诺。不默认抓取并复制整篇外部文章。
- 打印保留编号、证据说明、来源和可读网址，不依赖 hover 浮层呈现必要信息。弹层如采用，必须支持关闭、焦点恢复与窄屏操作。

### 验收

覆盖普通脚注、一源多引、多源支持同一论断、带页码引用、原文链接与补充来源、缺失元信息、失效网址及未核验来源。逐条核对“论断—证据—出处”关系；验证锚点、返回、键盘、手机、无脚本与打印。无真实依据的引用不得作为增强内容交付。

## 随功能执行的质量工作

- 每项功能使用新会话完成至少一次从 Markdown 到离线 HTML 的冒烟，不提供旧 HTML 作为必需依赖；失败输入保留为回归案例。
- 真实图片、SVG、公式资源的路径与内嵌验证跟随对应功能，不建设独立资源平台。
- 优先复用现有检查，只在出现重复且客观的检查需求时提取辅助脚本；不要求先完成面向任意 Markdown 的通用校验器。
- 自动检查负责遗漏、网络请求、运行错误、锚点和溢出等可判定问题；公式含义、图形关系、证据适配及阅读质量仍需逐项审阅实际产物。
- 跨浏览器、屏幕阅读器和性能检查随新增表面补充，报告实际环境与未验证项；不以跨模型基准建设阻塞功能。

## 暂不实施

- 独立生成 CLI、Agent 适配/编排框架、自建权限或沙箱系统。
- PDF/OCR、多文档合集、批量构建、实时编辑预览。
- 后端、账号、云批注同步、主题市场、插件系统。
- 没有真实容量或耗时问题前的长文分治和标注懒初始化。
- 无依据的图形、模拟、计算器与循环审美重做。
