# Papyra 需求文档

## 1. 项目定位

Papyra 是一份把文档变成美观、可交互 HTML 阅读页面的自包含 Skill。生成工作交给用户本地已安装并配置的 coding agent，Skill 不写死页面模板。

核心价值不是普通的 Markdown 转 HTML，而是让 agent 理解文档内容，为每篇文档设计适合人类阅读的信息结构、排版和必要交互。

本文记录产品要求与支持边界，不代表全部场景已验证。当前交付状态见 README，后续优先级见 [改进路线](roadmap.md)。

## 2. 使用场景

面向值得认真阅读、分享和保存的成品文档，例如：

- 技术说明：突出章节层级，改善代码、表格和引用的阅读体验。
- 研究报告：清楚呈现摘要、论据和结论之间的关系。
- 教程：提供步骤导航、示例展示和渐进展开。
- 产品介绍：根据内容组织视觉叙事与信息分区。

首版不以实时 Markdown 编辑预览为目标。与确定性转换相比，agent 生成需要更长时间，也可能消耗用户的模型额度。

## 3. 核心功能

### 3.1 输入

- 首版支持 Markdown 文件及其关联的本地图片。
- 本地资源路径相对于输入文档解析。
- 支持中文、英文及混排内容。
- PDF、OCR 及其他格式暂不纳入实施计划；其文本提取和阅读顺序恢复不属于当前 Skill 的交付范围。

### 3.2 输出

- 输出可直接通过浏览器打开的单个 HTML 文件。
- 建议首版以离线阅读为交付标准：CSS、JavaScript 和必要图片内嵌，不依赖 CDN、在线字体或外部脚本。
- 保留正文中的外部链接；离线阅读不要求链接目标可离线访问。
- 输出位置明确，失败时不得将不完整产物报告为成功。

### 3.3 内容驱动的设计

- agent 根据文档类型、结构与内容选择布局和交互，而非套用固定模板。
- 设计自由不等于没有标准：页面应保持内容保真、清晰层级、响应式布局和基本无障碍。
- 交互服务于阅读，不为展示能力强行增加功能。目录导航、章节折叠、代码复制等按内容需要提供。
- 不要求多次生成的视觉结果完全一致，但内容完整性与基本阅读质量应稳定。

### 3.4 内容保真

- 默认保留原文内容与含义，不静默删减、改写结论或新增事实。
- 保留代码、表格、引用、链接和图片表达的信息。
- 可以调整视觉呈现和信息分区，但不得破坏步骤顺序、引用关系或上下文含义。
- 如增加摘要，应明确标注为生成摘要，不能替代或隐藏原文。
- 文档超出处理能力时应明确失败，不得偷偷截断。

### 3.5 数学、图形与引用

以下要求已在 Skill 0.4.0 提供规则、资源、辅助模块与新样例；实际验证范围见 README，实施范围与验收见 [改进路线](roadmap.md)，不代表任意输入与浏览器均已验证。

- **数学公式**：支持行内与块级 LaTeX 的离线呈现，保留可取回的原式、公式编号与正文引用；窄屏和打印可读，错误明确报告，不静默改写数学含义。
- **原生 SVG**：完善输入 SVG 的安全显示与 LLM 直接生成内联图形的规范。保留原图信息与出处；生成示意图作为增强独立标记，关系有原文依据，不执行 SVG 中的脚本或外部依赖。
- **引脚式引用**：正文引用标记关联脚注、证据说明与参考来源，支持跳转和返回；按已有信息保留原出处、原始网址、作者、日期与页码。新增外部证据需实际查阅并独立标记，未核验或缺失信息如实说明，不伪造引用。
- **离线与打印**：公式、图形、证据说明与来源列表内嵌；原网址可供联网访问，外部链接目标不属于离线交付承诺。必要信息不依赖悬停才能查看。

## 4. 交付形态

Skill 是唯一产品入口，在 agent 内部直接调用，使用当前 agent 完成文档分析与页面生成。

Skill 提供设计指导、内容保真规则、固定资源和交付检查要求。模型调用、文件与浏览器工具及权限控制复用宿主，不开发独立生成 CLI 或 Agent 调用适配层。仓库样例构建与检查脚本用于开发验证，不构成第二套产品入口。

## 5. 阅读质量与执行安全

### 阅读质量

- 在桌面与手机宽度下可读，正文不因布局而丢失。
- 正文可选择、可检索，不能仅以图片或画布承载。
- 交互具备基本键盘可操作性、清晰标签和可见焦点。
- 正文具有足够的对比度；代码与宽表格可独立滚动。
- 打印时正文完整，折叠内容不能因此丢失。

### 执行安全

- 文档是输入数据，不能改变工具的执行规则或权限。
- 在专用输出工作目录中执行；源文件只读，不修改用户项目中的无关文件。
- 使用 agent 可提供的权限限制，不能仅靠提示词约束执行行为。
- 不执行文档中的命令，不自动加载生成页面中的远程脚本。
- 失败不应损坏源文件或已有有效产物。
- “本地 agent”不等于“本地模型”：文档可能被所选 agent 发送到模型服务，使用说明应明确这一点，不承诺数据不出设备。

## 6. 首版范围

### 包含

- Markdown 与关联本地图片输入。
- 内容驱动的页面设计与必要的轻量交互。
- 可离线阅读的单文件 HTML。
- 内容保真、响应式布局和基本无障碍。
- 自包含 Skill 入口与明确的宿主能力要求。
- 基本产物检查与明确的失败反馈。

### 暂缓

- PDF 及其他输入格式。
- 批量构建与实时预览。
- 主题市场、插件系统和复杂配置。
- 自动多轮审美评分与反复重做。

围绕数学公式、原生 SVG 与引脚式引用持续改进实际文档的阅读质量。全新上下文冒烟、真实资源验证及可复用检查随功能执行，不设为独立产品阶段。

## 7. 验收标准

准备一组小型代表文档，覆盖短文、长文、代码、表格、图片及中英文混排。

首版验收至少满足：

1. 原始文档与关联资源不被修改。
2. 能生成一个可打开的 HTML 文件，断网后正文、样式、图片和本地交互仍可用。
3. 正文内容、关键限制、代码、表格及引用没有静默遗漏或改变；生成摘要有明确标记。
4. 桌面和手机宽度下可阅读，键盘可操作主要交互，打印保留正文。
5. 页面结构与交互适合文档内容，不以装饰牺牲可读性。
6. agent 不可用、输入不合法、资源缺失或生成失败时，提供明确反馈，不报告成功或覆盖已有有效产物。
7. 超出文档处理边界时明确告知，不产生冒充完整结果的截断页面。

文件存在不等于验收通过。宿主按 Skill 要求执行可用的自动检查，并明确报告未验证项；内容保真和设计适配还需通过代表样本的实际页面评审，不以简单计数代替语义判断。

## 8. 待确定事项

- 不同宿主执行 Skill 的能力边界与实际验证环境。
- 远程图片的下载、内嵌与失败处理策略；离线成品不能静默保留在线图片依赖。
- 数学公式渲染器与语法边界、输入 SVG 的兼容范围，以及脚注与参考文献标识的解析约定。
- 文档长度、资源大小和生成耗时的支持边界。
- 产物自动检查的具体范围与实现方式。
