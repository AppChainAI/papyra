# Papyra Skill 样本测试

## 结论与范围

2026 年 10 月 2 日，将 Skill 从 0.1.0 优化为 0.1.1，并从三个原始 Markdown 重新渲染全文，保留首轮有依据的阅读增强与交互，重新设计阅读框架、排版和手机布局。

三个页面通过全文文字保真、离线打开、主要交互、代表性键盘操作、窄屏与 200% CSS 缩放检查。Impeccable 源码及桌面渲染扫描无告警；手机扫描有两条横向表格误报，已对照实际画面解释，不隐藏告警。

本轮由修改 Skill 的同一个 agent 执行，沿用首轮交互和既有上下文，使用临时生成脚本；不是独立评审、盲测或多次生成稳定性评测。尺寸和体积对照仅描述这些产物的变化，不能证明 Skill 修改本身导致了效果提升。CLI 未实现，没有固化页面模板。

## Skill 优化

- 增量改编 Impeccable 的 Read、排版、布局、polish 与有限自检原则，保留既有 oil-ui 指导。
- 正文保持安静，把内容个性放在导航、章节与图表组织中，不以换色替代设计。
- 明确字体角色、中文与英文行长差异、数值对齐、视觉和键盘顺序，以及手机目录的空间占用。
- 检查先看实际阅读任务，再看检测器；批量检查、集中修正、至多一次确认，不无限审美抛光，也不跳过失败的必需验收。
- 不引入整套 Impeccable Skill、启动器、自动下载、hooks、在线字体、选稿服务或产品档案。
- 改编文件标明修改与来源，Apache-2.0 许可随 Skill 一同分发。

## 页面生成效果

### 市场运营：围绕结论、口径与行动复盘

用横向章节目录、强调结论的正文和渠道比较组织复盘，不创建大型指标封面。正文列比首轮收窄，数值列实际右对齐；手机宽表格固定第一列，其他列局部滚动。

保留渠道选择、成本比例条、行动定位和预算试算，比例条标出 160 元警戒位置。付费渠道仍明确“周汇总不能证明连续两天超标”；预算试算仍保留公式、上限和未来效果不保证的说明。

验证邮件、社区、付费三渠道；20/50/180 元成本；行动锚点；约 242 个报名的历史成本试算；超预算 9,600 元以及负数、空值、错误步长反馈。

取舍：桌面目录比首轮占用更多纵向空间；渠道增强区在 390px 下由约 537px 增至 602px，操作目标和文字更大，但没有缩短这一部分。

### 需求开发：规则索引与紧凑状态关系

左侧章节索引、稳定的技术规格排版、明确的代码与状态角色。移除增强区内的多层卡片；手机把 queued/running 主路径与三个并列终态分开，不再将全部状态垂直堆叠。

390px 下默认状态增强区从约 883px 缩短至 534px。三种终态仍注明“不是顺序”，queued → cancelled 与 running → cancelled 路径保留；这不是正在运行的任务模拟。

验证五种状态的规则与单一选中状态；failed → T05 跳转；取消原子提交边界；代码复制不可用分支和捕获适配器成功分支。成功分支不等于实测系统剪贴板权限。补测 Enter 激活状态按钮。

### 设计方案：方案取舍与功能面积

采用与原文深蓝导视相呼应的框架、系统宋体标题和安静的阅读列。A/B 切换同时呈现席位、成本、声音边界、管理视线、调整成本与原表选中列，不隐藏另一方案。

功能面积图改为严格按 38/24/14/20 分配的无文字比例条，区域名称与面积置于独立按钮。避免窄区域里的文字挤压，也不让按钮内边距改变面积比例。图仍只对应 B，明确不是施工图；A 缺少分区面积，不编造数据。

验证 A/B 金额、席位、预算余量、取舍与快速反向切换；四区用途、通道风险和原表关联；比例误差小于总宽的 0.1%；补测 Space 激活区域按钮。

## 浏览器验收

使用本机 Chrome 无头浏览器，通过 `file://` 打开，Playwright 上下文禁用网络。检查脚本在 [samples/papyra/check.mjs](../samples/papyra/check.mjs)。三个页面均通过：

- 排除新增增强后，原文标题、段落、列表、表格、代码及限制文字与 Markdown 渲染结果一致；文字一致不替代语义检查。
- 外部 HTTP 请求 0，JavaScript 异常 0，页内链接目标存在；源文件检查前后哈希不变。
- 原有阅读勾选、邻近计数与清除可用，不冒充业务完成或测试通过。
- 1440×1000、390×844、320×844 无整页横向溢出，按钮文字未横向裁切，正文宽度受限，数值列右对齐。
- 目录随宽度变化：桌面展开、手机收起，可通过键盘展开并跳转；Tab/Enter 跳过目录入口可用。
- CSS 200% 缩放无整页溢出；减少动态效果取消平滑滚动；禁用 JavaScript 后正文和全部章节仍可见。
- 打印入口与样式通过，生成 2/3/3 页 PDF；查看了各 PDF 首页。

批量检查发现目录只在首次加载时判断宽度，桌面缩到手机仍展开；已改为监听断点变化，并留下回归断言。实际查看桌面首屏、手机首屏、正文深处、交互状态、手机状态区与面积区，以及打印首页，未见这些画面中的关键信息遮挡。

另用 macOS PDFKit 提取全部 PDF 文字，原文非空白字符的数量均被覆盖。但 PDFKit 会重排部分中文跨行文字，整段匹配不可靠；字符计数和首页查看不能证明 PDF 阅读顺序、逐页布局或完整语义保真。没有把这一辅助检查计为完整打印认证。

## Impeccable 检测结果

检测工具固定为 npm `impeccable@4.1.0`，安装在临时目录，不加入本仓库依赖，也未安装 hooks。扫描均使用 `--no-config`，不通过配置隐藏提示。

| 检查 | 本轮结果 | 解释 |
| --- | --- | --- |
| 三份 HTML 源码 | 0 条，退出 0 | 仅表示源码扫描未发现规则覆盖的问题 |
| 桌面渲染 1440×1000 | 0 条，退出 0 | 不代替实际画面检查 |
| 手机渲染 390×844 | 2 条，退出 2 | 两条均为 `edge-flush-cards` |
| 故意构造的坏页面 | 退出 2 | 源码与渲染模式都检出问题，验证检测器未空跑 |

手机提示分别位于运营页与方案页的 `div.table-wrap`，示例节点是 `th`，不是圆角卡片。运营页第一列有意固定在左侧，方案页保留完整比较表；实际画面和局部滚动检查未显示卡片边缘裁切。裁定为横向表格被套用卡片规则的误报，保留原始结果，不加全局忽略。首轮手机扫描同类提示为三条；告警数量变化不是审美提升分数。

本地证据在 `samples/papyra/evidence/`：`checks.json`、`comparison.json`、`impeccable-static.json`、`impeccable-browser-1440x1000.json`、`impeccable-browser-390x844.json`、截图和 PDF。这些文件不纳入 Git；比较测量与 PDFKit 辅助检查为本轮临时工具，不由常规检查脚本重新生成。

## 剩余边界

- 手机运营与方案宽表格仍需要横向滚动；没有为了减少滚动删列或隐藏另一方案。
- 框架、排版与状态布局有可观察变化，但没有测量真实读者的理解准确率与查找耗时。
- 键盘只覆盖代表性入口和操作，不是完整读屏或无障碍认证；也未跨浏览器测试。
- 未覆盖真实图片、超长文档、公式、脚注、恶意文档、其他 agent 或独立上下文多次生成。
- 本轮证明新版指导可用于完成这些阅读页面，不能宣称生成稳定性或普遍审美提升已验证。

## 复现

常规离线、文字、交互和布局检查：

```sh
TOOLS=$(mktemp -d)
npm install --prefix "$TOOLS" --no-audit --no-fund playwright marked
node samples/papyra/check.mjs "$TOOLS/node_modules"
```

需要 Node.js 22+ 和 Google Chrome；非默认 macOS 浏览器路径通过 `CHROME_PATH` 指定。运行更新本地截图、PDF 和 `checks.json`，不生成新的 HTML，也不修改输入。

可选 Impeccable 验收，使用单独临时安装，避免向项目安装 hooks：

```sh
DETECTOR=$(mktemp -d)
npm install --prefix "$DETECTOR" --no-audit --no-fund impeccable@4.1.0
CLI="$DETECTOR/node_modules/impeccable/cli/bin/cli.js"
node "$CLI" detect --json --no-config samples/papyra/*.html
node "$CLI" detect --json --no-config --viewport 390x844 \
  "file://$PWD/samples/papyra/market-operations.html" \
  "file://$PWD/samples/papyra/requirements-development.html" \
  "file://$PWD/samples/papyra/design-proposal.html"
```

检测器 npm 入口要求 Node.js ≥22.18，首次安装可能下载平台二进制；渲染扫描还需本机受支持的浏览器。退出 0 为无主要提示，2 为有提示，1 为扫描失败。没有检测器时，Skill 仍可生成和验收页面。
